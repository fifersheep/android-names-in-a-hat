<a id="navigation"></a>
## Navigation

One activity with Navigation 3 and typed destinations (NAM-7).

| Destination | Arguments | Shows | Notes |
|---|---|---|---|
| `Lists` | — | [Lists](#screen-lists) | Home. The only top-level destination: no navigation bar or rail |
| `Draw` | `listId: Long` | [Draw](#screen-draw) | Opening it sets the active list ([Launch](#launch)) |
| `EditList` | `listId: Long?`, `isNew`, `session` | [Edit list](#screen-edit-list) | `null` = create a new list. Added by NAM-7: `isNew` (the list was created in this visit, so Done goes to Draw; rule 2) and `session` (one per visit, used as the entry's content key, so rule 1's replace keeps the screen's state) |

These are **in-screen layers, not destinations:** the [Reveal](#reveal) (Draw screen state, kept in saved state), the [About](#about) sheet and all menus and snackbars.

Back-stack rules:
1. **Lists → New list** pushes `EditList(null)`. When the list name is first committed and the list is created, the entry is **replaced** with `EditList(id)`. This way restoring after process death can't create the list a second time: `GroupEditor.create` always inserts (`shared/.../usecase/GroupEditor.kt:13-16`).
2. **Done on a newly created list** replaces `EditList(id)` with `Draw(id)`. The stack is then `[Lists, Draw(id)]`, so back goes to Lists.
3. **Done or back on an existing list** pops back to wherever it was opened from (Lists or Draw).
4. **Lists → a list** pushes `Draw(id)`. **Draw → Edit list** (overflow) pushes `EditList(id)`. **Draw empty state → Add names** pushes `EditList(id)`.
5. **Back from Draw** always lands on Lists, including after launching straight into Draw: the shell seeds the stack as `[Lists, Draw(id)]`.
6. Predictive back on every pop (Android 14+), with the system back-to-home animation from Lists.

Screen tickets: Lists = NAM-8; Edit list = NAM-8 (the list-name header) **and** NAM-9 (the names section); Draw = NAM-10 + NAM-12; shell and back stack = NAM-7.

<a id="launch"></a>
## Launch and the active list

- **Splash:** the platform splash screen. Background `#35319A`, with the Top Hat icon foreground ([Theme](#icon)). It stays up only until the launch route is known, not until the database is ready (NAM-7).
- **Route:** if an active list is stored **and still exists**, open `[Lists, Draw(id)]`; otherwise `Lists`. A stale id is cleared.
- **Set:** opening Draw sets the active list (`ActiveGroup.open`).
- **Cleared:**
  - On a phone, by an **explicit back-out** from Draw to Lists (back gesture or Up).
  - On large screens, by deleting the list.
  - On large screens the Lists pane is always visible, so it never counts as "left". Picking another list **replaces** the active list.
- **Deleted:** deleting the active list clears it (`GroupEditor.delete` already does, `GroupEditor.kt:29-34`).

<a id="screen-edit-list"></a>
## Edit list

One screen for creating a list, renaming it and editing its names (D3). Mock-ups: `PhoneEdit`, `LandPhone`, `LargeEdit`.

**Portrait, top to bottom:**
- **Top app bar:**
  - Up arrow.
  - Title "New list" or "Edit list".
  - Trailing **Done** text button, enabled once the list exists.
- **List name field:** outlined, label "List name", placeholder "e.g. Year 5 Maple", in headlineSmall.
  - The IME action is **Next**.
  - **Committing** the name (Next, or focus moving to another field with non-blank text) creates the list, or renames it ([Navigation](#navigation) rule 1).
  - **Back or Up on a new list before its name is committed discards the typed text and creates nothing.** Focus lost because of back never commits. On an existing list, back commits a non-blank change to the name; a blank one is discarded and the old name is kept.
  - Blank on commit → "Enter a list name" ([States](#states)).
- **Names header:** "24 names" (plurals), labelSmall.
- **Names list:** in the order added, lazy, keyed by name id.
  - Each row: the name (bodyLarge), then a trailing delete icon button ("Delete Ada").
  - **Tap a name to rename it inline (D13).** The row becomes a text field with ✓ and ✕; IME Done saves; a blank value shows "Enter a name" and keeps the old name.
- **Add-name field, docked at the bottom above the keyboard:**
  - Label "Add a name", placeholder "e.g. Ada", a trailing **Add** icon button, IME action **Send** (label "Add").
  - Adding clears the field and **keeps focus and the keyboard** (NAM-9).
  - The list scrolls to show the new name.
  - Disabled, with the supporting text "Name the list first", until the list exists.
- **Delete a name:** the row disappears and a snackbar reads "Ada deleted" with **Undo** ([Delayed delete](#delayed-delete)).
- **Duplicates** are allowed, with no warning (D14). `validateLabel` trims only the ends (`shared/.../usecase/Labels.kt:9`), so a pasted "Ada\nBen" would keep its inner line break. ⇢ NAM-9 replaces inner line breaks and tabs with single spaces before validating. There is no bulk import (NAM-9 out of scope).

**Landscape:**
- A small top app bar, with the list name field on the same row as the title.
- The names list fills the space.
- The add field stays docked above the keyboard.

**Portrait, top to bottom:**
1. **Top app bar** (medium flexible).

   - Row 2: the list name in the display face (headlineLarge).
2. **[Select-all header](#select-header)**, sticky.

4. **[Draw bar](#draw-bar)**, docked at the bottom.

**Landscape (compact height):**
- A single-row top app bar: Up, then the title (titleLarge, display face), then sort, Reset and the overflow.
- The header and chips fill the leading area.
- The draw bar becomes a **trailing vertical panel** (~200 dp): the stepper stacked vertically, with **Draw n** below it.

<a id="select-header"></a>
### Select-all header (D18)

A 56 dp row under the app bar, with a bottom divider (`outlineVariant`). It is a single **tri-state checkbox** whose label is the counter, so both are one control.

The box reflects only the names you can toggle on their chips: the **not-drawn** names. Drawn chips don't show their selection, so counting them would let the box change with no visible cause. ⇢ NAM-10/NAM-12 compute `allSelected` over not-drawn names (today `DrawState.kt:33` counts every name). Tapping it still selects or clears **every** name, including drawn ones, which is harmless because drawn chips look the same either way.

| State | Condition (over not-drawn names) | Box | Label example | Tap |
|---|---|---|---|---|
| All | every not-drawn name selected | `primary` fill, `onPrimary` ✓ | "24 of 24 in the hat" | Clear all |
| All, some drawn | same, with some drawn | same as All | "20 of 24 in the hat · 4 drawn" | Clear all |
| Some | some selected | **tonal dash**: `primaryContainer` fill, 2 dp `primary` border, `primary` dash | "15 of 24 in the hat" | Select all |
| None | none selected | 2 dp `onSurfaceVariant` border, empty | "0 of 24 in the hat" | Select all |
| Disabled | every name drawn | `onSurface` at 38%, empty | "0 of 24 in the hat · 24 drawn" | — (Reset first) |

- The counter's number is **in the hat** (selected and not drawn) out of all names. "· n drawn" appears once n > 0.
- Select all and Clear all change **selection only**, never drawn state (`NameEditor.selectAll/clearAll`).
- TalkBack: a checkbox with state checked / mixed / not checked, labelled "Select all, 15 of 24 in the hat".
- The tonal fill alone is 1.23:1 against `surface`, which is why the "some" box needs its border ([Contrast](#contrast)).
- Canvas: build from `PhoneDraw` / `DrawScreen`, which use the chosen Top Hat palette and the tonal dash. `SelectCompare` and `MixedOptions` are the **superseded** comparisons the choice was made from: `SelectCompare` defaults to another palette and the filled dash.

<a id="chip-states"></a>
### Chip states (D9)

The `selected` and `drawn` flags are independent (`shared/.../model/Name.kt:6-7`). The chip shows **three visuals for four combinations**:

| selected | drawn | Visual | Label colour / fill | Icon | Text | TalkBack | Tap |
|---|---|---|---|---|---|---|---|
| ✓ | — | **In** | `onSecondaryContainer` on `secondaryContainer` | ✓ check | normal | "Ada, in the hat" | Deselect |
| — | — | **Out** | `onSurfaceVariant`, 1 dp `outline` border, no fill | none | normal | "Ben, out of the hat" | Select |
| ✓ | ✓ | **Drawn** | `onSurfaceVariant` on `surfaceContainerHigh` | ticket | ~~strikethrough~~ | "Chloe, drawn" | Opens menu |
| — | ✓ | **Drawn** | same as above | ticket | ~~strikethrough~~ | "Chloe, drawn" | Opens menu |

- Chips are full pills, at least 40 dp tall with a 48 dp touch target, with labelLarge text. Long names wrap within the chip, up to 2 lines.
- **Drawn is never colour alone:** it always has the icon, the strikethrough and the state description (NAM-12 AC10).
- **Put back in the hat:** tapping a drawn chip opens a menu anchored to it with one item, "Put back in the hat". It is also a custom TalkBack action. Putting back clears `drawn` **and** sets `selected = true`, so the name really is back in the hat.
  - **Hand-off:** this needs a per-name un-draw (clear drawn for given ids). NAM-5 merged with only `markDrawn(ids)` and `clearDrawn(groupId)`, so **NAM-12 adds it** to `NameRepository` and `RoomNameRepository`.
- Toggling selection saves immediately and animates the fill with the fast spatial spring ([Motion](#motion)).

<a id="draw-bar"></a>
### Draw bar (D6)

Docked at the bottom on a `surfaceContainer` background, with 12 dp padding, plus the navigation-bar inset.

| Situation | Content |
|---|---|
| In the hat ≥ 1 | **Stepper**: a connected button group [− n +], 48×56 dp segments, `surfaceContainerHigh`. Beside it the **Draw n** button: filled, `primary`, a 56 dp full pill that takes the rest of the width |
| In the hat = 0, and no **selected** name is drawn | The stepper is hidden. The bar shows "Tap names to put them in the hat" and a disabled **Draw** button. Reset stays in the top bar if anything is drawn |
| In the hat = 0, and at least one **selected** name is drawn (every selected name has been drawn) | The stepper is hidden. The bar shows "Everyone's been drawn" and a filled **Reset** button |
| List has no names | The bar is hidden; see [States](#states) |

- n starts at 1. It is clamped to 1..in-the-hat whenever the pool changes (NAM-10 rabbit hole), and kept per list in saved state.
- − is disabled at 1 and + at the maximum.
- The live value is announced politely.

<a id="draw-from-remaining"></a>
## Draw from remaining (NAM-12)

- **Always on (D8):** every draw picks from **in the hat** only, and marks the drawn names as drawn. Drawn state persists per list.
- ⇢ **The remaining pool is new code.** `DrawState.selectedCount`/`options`/`canDraw` (`DrawState.kt:28-35`) and `NameDraw.drawFrom` (`NameDraw.kt:22`) count selected names **including drawn ones**. NAM-12 makes all of them use selected-and-not-drawn; the counter and stepper max follow.
- **Minimum to draw = 1 (D7):** one name left in the hat is a valid draw. NAM-12/NAM-10 change `MIN_NAMES_TO_DRAW` to 1 (`shared/.../draw/DrawState.kt:10`) and apply it to the remaining pool.
- **Reset:**
  - Where: a top-bar icon button, enabled when any name is drawn. When the hat is empty, it is also the draw bar's main action.
  - What it does: clears drawn for the whole list. It never changes selection.
  - Feedback: a snackbar, "Drawn names reset", with **Undo**, which restores the previous drawn set.
  - There is no confirmation dialog.
- **Undraw one:** "Put back in the hat" ([Chip states](#chip-states)).
- **New names** start selected and not drawn, so they join the hat (NAM-12 rabbit hole). A deleted name takes its drawn state with it.
- **Upgrades from 2.7.0:** nothing is drawn, so the first draw behaves as before.

<a id="reveal"></a>
## Reveal — the draw moment (D10)

The reveal replaces 2.7.0's alert dialog. Mock-ups: `RevealPhone`, `RevealLand` and `RevealLarge` (animated), `RevealEnds` and `RevealReduced`.

- **Order:** compute the draw → persist the drawn flags (one step; never show a result that wasn't saved) → then animate. The animation never changes the outcome.
- **Surface:** a **full-window takeover** on every size. On large screens it covers both panes, because a teacher may be projecting.
  - Backdrop: `primary` in light, `primaryContainer` in dark.
  - Sparkles: `tertiaryContainer` in light, `tertiary` in dark.
  - Title "Out of the hat", in the display face, `onPrimary` / `onPrimaryContainer`.
- **Sequence (expressive motion):**
  1. The hat illustration shakes: rotation ±6°, 3 cycles, ≤ 600 ms.
  2. Name cards pop out of the hat one by one, with a spatial spring overshoot (`MotionScheme.expressive()` default spatial spec), staggered 250 ms apart. For n > 4, the stagger is `min(250, 900 / (n − 1))` ms, so the last card **starts** by 1.5 s (600 ms shake + ≤ 900 ms of stagger). Its spring then settles in about 300 ms more, so the whole reveal is done in under 2 s.
  3. The cards settle into the end layout.
- **End layout:**
  - Each card is `surfaceContainerLowest` with the name in displaySmall (display face) on `onSurface`. On phones they stack in a column; on large screens they form a grid. Many names scroll.
  - Buttons at the bottom:
    - **Done**, outlined, which dismisses: a 2 dp border and label in `onPrimary` (light) / `onPrimaryContainer` (dark).
    - **Draw n more**, which draws `min(n, left)` again from the hat. It is filled `surfaceContainerLowest` with a `primary` label in light, and filled `primary` with an `onPrimary` label in dark. A default `primary` button would vanish on the light `primary` backdrop.
  - When the hat is now empty, "Draw more" is replaced by the line "Everyone's been drawn".
- **Dismiss:** Done, back (with a predictive-back preview), or Escape on hardware keyboards.
- **State:** the result names are held in saved state on the Draw destination. Rotation and process death show the same result (NAM-10 AC9).
- **TalkBack:** when the reveal opens, the full result is announced at once ("Drawn: Ada, Sam and Tom"), without waiting for the animation. The cards are not focus-trapped behind the animation.
- **Landscape:** the hat sits at the start and the cards in a 2-column grid at the end. The buttons go in a trailing column.
- **Reduced motion:** see [below](#reduced-motion).

<a id="large-screens"></a>
## Large screens (D16)

Breakpoints come from `currentWindowAdaptiveInfoV2()` (WindowSizeClass V2):

| Window | Layout |
|---|---|
| Width < 600 dp | Phone single pane (portrait specs above) |
| **Height < 480 dp** (compact height) | Phone **landscape** specs, single pane, whatever the width |
| Width 600–839 dp, height ≥ 480 | Single pane; content max width 840 dp, centred; Draw chips use the extra width |
| **Width ≥ 840 dp and height ≥ 480 dp** | **List-detail**: a Lists pane (360 dp; 400 dp at ≥ 1600 dp width) + a detail pane |

List-detail:
- **Panes:**
  - The Lists pane is the [Lists](#screen-lists) screen without the large title collapse. The FAB sits at the bottom of the pane.
  - The detail pane shows `Draw(id)` or `EditList(id?)`. Edit list replaces Draw in the detail pane, and back returns to Draw.
- **Selection:** the selected list's card uses a `secondaryContainer` fill.
- **Deleting the open list** from the Lists pane closes the detail at once: it shows the "Pick a list" placeholder, and the active list is cleared. **Undo** restores the list and reopens it in the detail pane.
- **No list open:** the detail pane shows the hat illustration and "Pick a list to draw from".
- **No lists at all:** the Lists pane shows the empty state, and the detail shows the same placeholder.
- **Reveal:** full window ([Reveal](#reveal)).
- **Implementation:** `ListDetailSceneStrategy` (adaptive-navigation3), which needs an opt-in to `@ExperimentalMaterial3AdaptiveApi` ([API stability](#api-stability)).

## Empty, error and validation states

| Where | When | Shows |
|---|---|---|
| Lists | No lists | Centred hat illustration, "No lists yet", body "Make a list of names, then draw them from the hat.", and the FAB. Replaces 2.7.0's arrow hint |
| Draw | List has no names | Hat illustration, "This hat is empty", "Add some names to start drawing." and a filled **Add names** button → `EditList(id)` (NAM-9 AC6). No header, no draw bar |
| Draw | Nothing in the hat, nothing drawn | The draw bar shows "Tap names to put them in the hat"; Draw is disabled |
| Draw | Every selected name drawn (none in the hat, at least one selected-and-drawn) | The draw bar shows "Everyone's been drawn" and **Reset** |
| Edit list | Blank list name on commit | Field error "Enter a list name"; focus stays (D15) |
| Edit list | Blank name on Add / IME send / inline rename | Field error "Enter a name"; nothing saved; focus and keyboard stay. Typing clears the error |
| Edit list | Typing a name before the list exists | The add field is disabled with "Name the list first" |
| Large | No list open | "Pick a list to draw from" |

Validation uses `validateLabel` (`shared/.../usecase/Labels.kt`): text is trimmed, and blank or whitespace-only input is rejected.

<a id="delayed-delete"></a>
### Delayed delete (D12)

Deleting a list or a name **hides it immediately** and shows a snackbar with **Undo** (default snackbar duration). The real delete is committed when the snackbar times out or is dismissed, or when the screen leaves composition.

**Undo** un-hides the item. Re-inserting is **not** used, because it would lose:
- the list's names: the cascade delete has already removed them (`GroupRepository.kt:23-24`)
- the sort order and the active list (`GroupEditor.kt:29-34`)
- a name's id, position and drawn state (`NameRepository.kt:14-18`)

The NAM-8 and NAM-9 ViewModels own the pending-delete state.

<a id="type"></a>
### Type

- **Display face: DM Serif Display**, bundled, one weight (Regular), OFL. Used for:
  - displayLarge–Small (reveal names)
  - headlineLarge–Medium (the Lists title, the Draw list title, "Out of the hat", empty-state titles)

  NAM-7 measures its APK cost.
- **Everything else** uses the system default (`FontFamily.Default`, Roboto) with the M3 type scale. Use the `*Emphasized` styles for the Draw button label and the counter.
- Text scales to 200% font size: chips and cards wrap, and nothing truncates names.

<a id="shape"></a>
### Shape

- Full pills (`CircleShape`) for chips, buttons, the sort button and the FAB.
- The stepper's outer ends are 28 dp radius and its inner joins 6 dp (connected button group).
- Cards, sheets and reveal cards use `extraLarge` (28 dp).
- Text fields use the M3 default.

<a id="motion"></a>
## Motion

`MaterialExpressiveTheme` / `MaterialTheme(motionScheme = MotionScheme.expressive())`. Spatial specs come from the motion scheme; never hard-code durations, except the reveal timings above.

| Where | Motion |
|---|---|
| Chip toggle | Fast spatial spring on a 0.96 press scale, plus a fast effects crossfade of fill and icon |
| Lists → Draw | Navigation 3 shared element: the card's title morphs into the Draw title (shared bounds). Predictive back scrubs it in reverse |
| FAB → New list | Shared bounds from the FAB container into the Edit list screen |
| Draw bar state changes | A default spatial spring on size: the stepper hides and Draw morphs into Reset |
| Delete | The item collapses (`animateItem`); the snackbar uses standard motion |
| Reveal | See [Reveal](#reveal) |

<a id="reduced-motion"></a>
### Reduced motion (D11)

There is no Compose API for this, so read `Settings.Global.ANIMATOR_DURATION_SCALE`. **When it is `0`:**
- Compose animations already finish in one frame (they honour the scale).
- The **reveal** keeps the hat but doesn't shake it, and skips the stagger. The end layout fades in with one crossfade, or appears instantly if the platform suppresses it. The result and announcement are identical.
- Shared-element transitions fall back to the default crossfade.

NAM-10 AC10 tests this.

<a id="accessibility"></a>
## Accessibility

- Touch targets are ≥ 48 dp. Every icon button has a content description from the copy deck (`action_back`, `draw_back`, `action_more`, `draw_count_group`, `edit_rename_save`, `edit_rename_cancel` and the others).
- Chips are toggleable with a role and a state description ("in the hat" / "out of the hat" / "drawn"). A drawn chip carries the custom action "Put back in the hat".
- Select all is one tri-state checkbox whose label includes the counter.
- The reveal announces the full result at once, and the cards are readable in order.
- Drawn state is never colour alone (icon + strikethrough + state description).
- All copy is in resources, with plurals for every count.
